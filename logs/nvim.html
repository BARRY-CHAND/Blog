I Use Neovim BTW.

Intro

This is log entry 4, being about me building my own Neovim config. Neovim is a modern, extensible terminal text editor and for those who don't know, it's not essentially an easy thing to do. It's like trying to "fill this up with an elite cine reference". So this took almost 4 days of my so-called study holidays for the semester.

First up looking Neovim can be overwhelming, and trust me using it will be a nightmare (speaking of experience). But eventually you will adapt to it and will start to enjoy. So lets start with my config


Food for thought

Before I thought of doing my own config, when I started with Neovim I was using a Neovim distro called LazyVim, by folke, and then moved on to NvChad, as my friend Theo K Laurent (Dorling) suggested it to me, saying he used it when he was using Neovim. After using that for about 6 months, when I wanted to add some more plugins, I ran into a problem: I didn't know how to add them. I watched some videos on adding those extras, and when I tried them, I realized that the file structure of the Neovim distro is way different from a normal one. So I thought of designing, or rather assembling, my own config.

The plan

Core first, everything else after. Basic options and the plugin manager, then plugins one at a time, and the NvChad look right at the end. The reason is simple: when something breaks, you know which layer did it. As Oliver Queen (Arrow) says sometimes you have to run beore you can walk.

Most of what I learned came from these YouTubers, my own Harisson Wells (mentor) of tutorials: Typecraft, TJ DeVries Tony and mainly Bread on Penguins. Go watch them. They explain it way better than I do.

A Speed Mirrage If you will.

I'm not going deep into each plugin. Think of plugins as lego blocks which combine to give a big lego build. The plugins which I use inmy config are:

  • lazy.nvim, the plugin manager. The most important part where everything gets built from here
  • gruvbox, the colorscheme
  • telescope, a fuzzy finder for files and text.
  • treesitter, proper syntax highlighting
  • neo-tree, the file tree I was missing in the plain config
  • mason + nvim-lspconfig, language servers (Lua, C, TypeScript, HTML and CSS on the way)
  • nvim-cmp + LuaSnip, autocomplete and snippets
  • none-ls, formatting with stylua, black, isort and clang-format
  • alpha, the start screen
  • barbar, buffer tabs
  • which-key, gitsigns, autopairs and a floating terminal. Not the main heroes, but every plugins improves the user experience.

Borrowing the NvChad look

I still liked how NvChad looked, so instead of going back to it, I pulled the UI parts into my own config (the statusline, which-key and the rest) while trying to keep gruvbox for the code colors. Basically an Arrowverse crossover: NvChad's looks in my universe, without its file structure. Hopefully no Crisis this time (an elite reference 🤓😎).

What's next

A few things are on the list. DAP for debugging, which means breakpoints and stepping through code inside Neovim, like Doctor Strange looking all possible futures in Titan in Avengers: Infinity War (another reference😎). After that, nvim-lint for some languages and a bit of cleanup. A config like this is never really finished. It's like upgrading and enhancing the legomodel i just built.

All's Wells That Ends Wells.

Was it worth 4 days of holidays? Yeah. I know every file in it, and when it breaks I know where to look, which was never true with a distro. Is it better than the million other configs out there? No. Will it be useful for anything for my exams? No. Does it matter that I configured this to anyone? Maybe No. But it's mine and I feel like "Tony Stark was able to built this in a cave, with a box of scrap."
